# DeepCybo Lite 单相机映射录制操作说明

本文档用于基础联调：现场只启动 1 路相机 `/camera1/image_raw/compressed`，但 Lite 功能包需要 3 路相机话题。我们用一个临时桥接节点把这 1 路图像复制成 3 路，再启动 Lite 记录节点保存 LeRobot / DoRobot 格式数据。

除 `/opt/ros/jazzy/setup.bash` 外，本文所有工程路径都按当前工作区根目录的相对路径书写。开始前请先进入工作区根目录。

## 1. 实验目标

确认以下链路可用：

```text
/camera1/image_raw/compressed
  -> /deepcybo/lite/camera/head/image_raw/compressed
  -> /deepcybo/lite/camera/wrist_left/image_raw/compressed
  -> /deepcybo/lite/camera/wrist_right/image_raw/compressed

/slave/lite/joint_states
  -> observation.state，16 维

/slave/remote_policy_controller/command
  -> action，16 维
```

录制成功后，数据会保存在 `/media/stvli/0EE4-E658/` 目录下，格式包含：

- `meta/info.json`
- `meta/episodes.jsonl`
- `data/chunk-000/episode_000000.parquet`
- `images/observation.images.image_head/...`
- `images/observation.images.image_wrist_left/...`
- `images/observation.images.image_wrist_right/...`

## 2. 开始前确认

先确认这些节点已经由现场同事启动：

- Lite 控制相关 ROS2 节点已经启动。
- `/slave/lite/joint_states` 有数据。
- `/slave/remote_policy_controller/command` 有数据。
- `/camera1/image_raw/compressed` 有图像数据。

本文档默认当前目录关系如下：

```text
当前工作区根目录
├── src/RoboDriver
├── src/RoboDriver/robodriver/robots/robodriver-robot-deepcybo-lite-aio-ros2
├── ../bar_ws
└── ../cam_ros2_ws

默认数据盘
└── /media/stvli/0EE4-E658
```

如果现场目录关系不同，请让熟悉环境的人先改命令中的 `../bar_ws` 和 `../cam_ros2_ws`。

## 4. 终端 0：检查输入话题

执行：

```bash
ros2 topic list -t
```

确认列表中能看到：

```text
/camera1/image_raw/compressed [sensor_msgs/msg/CompressedImage]
/slave/lite/joint_states [sensor_msgs/msg/JointState]
/slave/remote_policy_controller/command [bar_msgs/msg/MITCommand]
```

再检查频率：

```bash
ros2 topic hz /camera1/image_raw/compressed
ros2 topic hz /slave/lite/joint_states
ros2 topic hz /slave/remote_policy_controller/command
```

正常现象：

- 相机大约 `30 Hz`。
- 机械臂话题大约 `30 Hz` 到 `50 Hz` 均可。
- 按 `Ctrl+C` 退出 `ros2 topic hz`。

检查关节名：

```bash
ros2 topic echo /slave/lite/joint_states --once --field name
ros2 topic echo /slave/remote_policy_controller/command --once --field joint_names
```

必须包含这 16 个名字：

```text
left_shoulder_pitch
left_shoulder_roll
left_shoulder_yaw
left_elbow_pitch
left_wrist_yaw
left_wrist_roll
left_wrist_pitch
right_shoulder_pitch
right_shoulder_roll
right_shoulder_yaw
right_elbow_pitch
right_wrist_yaw
right_wrist_roll
right_wrist_pitch
left_gripper
right_gripper
```

顺序可以不同，Lite 功能包会按名字自动重排；当前 canonical 顺序为原 14 个 arm joints 后追加左夹爪、右夹爪。

## 5. 终端 1：启动单相机到三相机的映射节点

打开新终端，先执行第 3 节环境命令，然后执行：

```bash
python -m robodriver_robot_deepcybo_lite_aio_ros2.mock_recording \
  --camera-source-topic /camera1/image_raw/compressed \
  --joint-states-topic /deepcybo/lite/mock_unused/joint_states \
  --command-topic /deepcybo/lite/mock_unused/command \
  --arm-rate-hz 1
```

保持这个终端不要关闭。

这个命令会做一件事：

- 把 `/camera1/image_raw/compressed` 复制到 Lite 需要的 3 路相机话题。

它不会向真实控制话题 `/slave/lite/joint_states` 和 `/slave/remote_policy_controller/command` 发布 mock 数据，因为命令里已经把 mock 关节/夹爪话题重定向到了 `/deepcybo/lite/mock_unused/*`。

重要提醒：

```text
真机控制节点已经启动时，不要直接运行不带参数的 deepcybo-lite-mock-ros2。
不带参数时会向 /slave/* 默认话题发布 mock 关节/夹爪数据，可能干扰真实控制链路。
```

## 6. 终端 0：检查映射节点拓扑

在终端 0 执行：

```bash
ros2 node list | grep deepcybo
```

应该看到：

```text
/deepcybo_lite_mock_recording
```

检查 3 路相机话题：

```bash
ros2 topic info /deepcybo/lite/camera/head/image_raw/compressed
ros2 topic info /deepcybo/lite/camera/wrist_left/image_raw/compressed
ros2 topic info /deepcybo/lite/camera/wrist_right/image_raw/compressed
```

每个话题都应该显示：

```text
Type: sensor_msgs/msg/CompressedImage
Publisher count: 1
```

也可以检查频率：

```bash
ros2 topic hz /deepcybo/lite/camera/head/image_raw/compressed
```

正常应接近 `30 Hz`。

## 7. 终端 2：启动 Lite 记录节点

打开新终端，先执行第 3 节环境命令，然后执行：

```bash
python src/RoboDriver/robodriver/robots/robodriver-robot-deepcybo-lite-aio-ros2/scripts/record_external_topics.py \
  --duration-s 20 \
  --fps 30 \
  --root /media/stvli/0EE4-E658/deepcybo_lite_ros2_camera1_external_20s \
  --repo-id deepcybo/lite-ros2-camera1-external \
  --overwrite
```

参数含义：

- `--duration-s 20`：录制 20 秒。
- `--fps 30`：按 30 Hz 保存。
- `--root ...`：保存目录；不指定时默认保存到 `/media/stvli/0EE4-E658/deepcybo_lite_external_ros2_<timestamp>`。
- `--overwrite`：如果目录已存在，先删除旧结果再录。

正常启动后，会看到类似日志：

```text
[DeepCybo Lite] node ready
[leader] 机械臂向量已恢复，继续写入缓存
[follower] 机械臂向量已恢复，继续写入缓存
[连接成功] 所有设备已就绪:
  - 摄像头: image_head, image_wrist_left, image_wrist_right
  - action (leader_arms): 16 维
  - observation (follower_arms): 16 维
Recording 600 frames at 30 Hz
```

录制完成后，终端会打印保存路径，例如：

```text
/media/stvli/0EE4-E658/deepcybo_lite_ros2_camera1_external_20s
```

## 8. 终端 0：录制时检查拓扑

记录节点运行期间，执行：

```bash
ros2 topic info /slave/lite/joint_states
ros2 topic info /slave/remote_policy_controller/command
```

正常应看到有订阅者：

```text
Subscription count: 1
```

检查相机话题：

```bash
ros2 topic info /deepcybo/lite/camera/head/image_raw/compressed
ros2 topic info /deepcybo/lite/camera/wrist_left/image_raw/compressed
ros2 topic info /deepcybo/lite/camera/wrist_right/image_raw/compressed
```

正常应看到：

```text
Publisher count: 1
Subscription count: 1
```

说明：

- `Publisher count: 1` 来自终端 1 的映射节点。
- `Subscription count: 1` 来自终端 2 的 Lite 记录节点。
- 录制结束后，记录节点会自动退出，`Subscription count` 变回 `0` 是正常现象。

## 10. 停止实验

录制节点会在录满指定时长后自动退出。

相机映射节点需要手动停止：

```text
回到终端 1，按 Ctrl+C
```

停止后检查：

```bash
ros2 node list | grep deepcybo
```

如果没有输出，说明本次实验相关节点已经退出。

## 11. 常见问题

### 记录节点一直等连接

看日志缺哪一项：

- 缺相机：检查终端 1 的映射节点是否还在运行。
- 缺 leader：检查 `/slave/remote_policy_controller/command` 是否有数据、`joint_names` 是否包含 16 个 canonical Lite joints。
- 缺 follower：检查 `/slave/lite/joint_states` 是否有数据、`name` 是否包含 16 个 canonical Lite joints。

### 只看到 Publisher count，没有 Subscription count

可能记录节点还没启动，或者已经录完退出。

### 数据不是 600 帧

检查录制命令里的参数：

```text
--duration-s 20
--fps 30
```

理论帧数为：

```text
duration-s * fps = 20 * 30 = 600
```

### 误启动了不带参数的 mock

如果不小心运行了不带参数的 `deepcybo-lite-mock-ros2`，请立即按 `Ctrl+C` 停掉，然后重新运行第 5 节的完整命令。

## 12. 本次验证结果参考

本次在现场环境中已验证：

- `/camera1/image_raw/compressed` 可以映射成 Lite 需要的三路相机话题。
- Lite 记录节点可连接真实 `/slave/lite/joint_states` 和 `/slave/remote_policy_controller/command`。
- 20 秒录制成功保存 600 帧。
- `action` 为 16 维。
- `observation.state` 为 16 维。
- 三路图像各保存 600 张。
